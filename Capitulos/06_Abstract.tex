\begin{center}
    \section*{Abstract} % Centraliza o título "Abstract" (sem numeração)
\end{center}

\par Supervisory control and data acquisition (SCADA) systems monitor, supervise and control industrial processes in real time, bringing together in a single interface the reading of field variables, historical logging, alarm signaling and the dispatch of commands to the equipment. Conventional systems, however, require proprietary licenses, dedicated hardware and specialized local installation, which keeps them out of reach for small and medium-sized enterprises. In view of this, this work presents the development and validation of a multi-client, service-oriented web supervisory system, executed in Docker containers and accessed through the browser with no client-side installation. The architecture separates the web interface, the application programming interface, the background processing workers, the Modbus TCP acquisition service and an isolated engine for running user code written in JavaScript. The PostgreSQL relational database stores the registry and the history, with a dedicated database for each client, and Redis keeps the current value of each point and the work queues, while the services communicate through a message bus (Moleculer). Access is controlled by role and by permission group, and the commanding of equipment follows four phases, namely selection, verification, confirmation and execution, with a lock per point, idempotency and an audit record. The concepts of supervisory systems, Industry 4.0, containers and orchestration that underpin the proposal are reviewed, and the system requirements are validated against the architecture. The validation combined automated tests, load campaigns and a test bench with a TM221 programmable logic controller and an ATV320 variable frequency drive. The measured results show the automatic creation of a client database in up to 3.4 s, history writing of about 9,400 rows per second for one client and the acquisition of up to 9,750 points every 30 s per replica of the acquisition service, besides 8 ms to apply one cycle of values in the synoptic screen. The requirements for commanding, alarms and replication still depend on bench trials and on measurements with more than one replica, and deployment on a cloud provider and on a container orchestrator is left as future work.
